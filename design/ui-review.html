现状取证

以下截图来自本地 vite dev 真实渲染，1440×900，默认主题。

英文页：面板存在、文本已渲染，但 完全不可读。下方那个"转圈"其实是重开按钮 ReloadOutlined。

中文双拼页：唯一"正常"的页面——因为它没走统一的打字面板组件，而是自己画了一套。

自定义页：输入框是 白底黑框的原生 TextArea，与深色主题完全脱节；下方面板同样不可读。

02

问题清单

按严重度排序。P0 影响可用性，必须立刻修；P1 决定"形象"，是本次升级的主体；P2 是打磨项。

P0

打字面板白底白字，三个模式不可用

面板背景复用了 --home-window-bg-color（本意是首页那张浅色卡片），文字色却取 --head-text-color。深色主题下两者都是近白色，正文彻底消失。这是"语义变量被跨场景复用"造成的典型事故。

public/themes/default.css:2-4 · TypingArea.less:11,16
把面板色从 --home-window-bg-color 解耦，新增独立的 --typing-panel-bg；40 个主题各自只需补一行。
P0

移动端整体失效

词块容器写死 min-width: 920px，打字区用 <Col flex="900px"> 固定宽度，页面没有任何断点。手机打开即横向滚动，模式导航被裁切。

Monkey.less:60 · TypingArea.tsx:200 · 全站无 @media
容器改 width:100%; max-width:900px，栅格去 Row/Col 化，加 768 / 480 两档断点；中文词块改 flex-wrap 自适应。
P1

没有品牌，只有"一个 antd 页面"

顶栏没有 logo、没有产品名，<title> 是 typing-cn，meta description 还重复写了两条。用户无法回答"这是谁做的、和别的打字网站有什么不同"。40 个主题是很好的资产，但没有一个统一的身份把它们串起来。

index.html:8-12 · Header.tsx 无品牌区
建立品牌层：标志 + 名称 + 一句定位；主题只改色，不改形。
P1

导航图标语义错误

「中文双拼 / 英文 / 代码 / 自定义」四个模式入口，统一用了 <BellOutlined /> 铃铛图标。铃铛代表通知，和打字模式毫无关系——这是复制模板时留下的占位符。四个入口权重完全相同，选中态只靠换色，扫视时找不到"我现在在哪"。

Header.tsx:128
改为分段控件（segmented），选中项用键帽浮起；图标按模式给语义图标或直接去掉。
P1

信息架构：全局设置与页面参数混在一行

第二行把「主题」「词组设置」（全局、低频）和「输入方案」「UI尺寸」（本页、高频）平铺在同一条线上，再靠 ROUTE_HEADER_CONFIG 按路由显隐。结果是：同一位置在不同页面出现不同东西，用户永远记不住哪里能改什么。

Header.tsx:15-21, 136-200
拆成三层：品牌 / 模式切换 / 设置入口（齿轮收纳全局项）；页面级参数（档位、换一段）下沉到内容区顶部。
P1

主操作长得像"加载中"

重开按钮是 90×90、纯图标、50% 不透明度，位置在面板正下方。圆形箭头 + 半透明，与 antd Spin 视觉同构，用户第一反应是"页面还没加载完"。它还是纯图标、无文字、无快捷键提示。

ReloadBtn.less:1-3,21-26 · ReloadBtn.tsx:19-24
改成带文字的次按钮「重新开始 ⌘R」，放在面板右下或操作条末端；图标 14px 即可。
P1

打字过程零反馈

WPM、准确率、用时只在打完那一刻出现（TypeResult 仅在 showResult 时渲染）。而打字练习的核心快感来自"实时看到自己在变快"。没有进度、没有实时速度、没有节奏感，练习就变成了盲打。

TypingArea.tsx:257-268 · TypeResult.tsx
面板上方常驻一条统计条（速度 / 准确率 / 用时），面板底部加 2px 进度线。
P1

版式没有统一轴线

中文页是 900px 左对齐的词块网格，英文页是 860px 居中的段落，筛选行却固定左内边距 30px。三种对齐方式共存，页面左右边缘参差，视觉上"散"。

English.less:7 · TypingArea.less:66,91 · Monkey.less:55
定义一个 1040px 内容容器 + 8px 栅格，所有区块共用同一左边缘。
P2

关键色对比度在及格线边缘

实测：主色 #1890ff 在 #282c34 上 4.31:1（12–14px 小字不达 AA 4.5）；错误红 #ff0000 3.50:1；主色按钮上的白字 3.24:1。README 里写"全部通过 WCAG 检查"，实际这几个值没过。

default.css:15,57,60
主色提到 #2AA79B（深底 5.4:1）；错误色改 #E0553F 并配 14% 底色；按钮文字改用深色底。
P2

中文词块的节奏不稳

每个词上方是 14px 拼音、下方是 22px 汉字，词块四周 margin:7px，拼音默认 inherit 色再压 60% 不透明。行与行的纵向间距被词块高度决定，扫读时视线要反复上下跳。

Monkey.less:61-84
拼音固定 12px / 字距 0.06em / 单独语义色；词块改 padding 控制，行高统一 1.9。
P2

主题选择器是 40 个色块

40 个纯色矩形平铺，只显示主题名，没有预览、没有明暗分组、没有搜索。用户选主题本质是"想看看效果"，这里只能盲选。

Header.tsx:260-279 · Header.less:75-89
改成两列卡片：左预览（背景+正文+主色三色条），右分组（深色 / 浅色 / 高对比）。
P2

缺空态与首次引导

进页面就是一块空面板，没有任何"点击开始"的提示。中文页有 4 行 12px 灰字说明（对比度虽够但字号偏小），英文/代码页则完全没有。

Monkey.tsx tip-line
统一一行 kbd 提示：「点击面板开始 · Tab 重新开始 · Esc 换一段」。
03

视觉方向

升级不是换配色，而是给这个产品一个"只属于它"的形状。方向来自产品本身：小鹤双拼 = 两键一字，键盘 = 唯一的核心道具。

鹤键
CraneType

「鹤」承接小鹤双拼的血脉——轻盈、精准、一笔到位；「键」说明它是工具，不是游戏。标志是一枚键帽，帽顶一道折线：两键相交，成一字。

Keycap 键帽Folded stroke 折线Two-key 双拼

标志在 16px 下仍可辨识：外轮廓是键帽，内部折线是唯一细节，不做渐变与描边堆叠。

母题一 · 键帽层级所有可交互表面（面板、按钮、选中态）都用同一套"键帽"物理：1px 顶部内高光 + 底部 2px 深色键脚 + 一层柔和投影。取代 antd 的纯平面按钮，让"按下去"这件事在视觉上成立。
母题二 · 双拼双色一字两键 → 一套双色系统。主色 鹤青 只给"已完成/正确"，辅助色只给"当前/待输入"。颜色不再是装饰，而是进度本身。
母题三 · 呼吸栅格8px 基准，内容容器 1040px，正文列 900px。行距统一 2.0，因为打字时眼睛要在同一行停留很久——这是唯一该"浪费"空间的地方。

06

实施路线

先止血，再换脸，最后打磨。每阶段结束都可独立上线。

PHASE 0

止血

约 0.5 天 · 可立即发
  • 面板 token 解耦，修白底白字
  • 重开按钮加文字
  • 去掉铃铛图标
  • 修 meta / title
PHASE 1

换脸

约 3–4 天 · 形象升级主体
  • 品牌标志 + 顶栏重构
  • 打字面板重做（层级 / 进度 / 统计条）
  • 统一容器与栅格
  • 响应式三档断点
PHASE 2

打磨

约 3 天 · 拉开差距
  • 主题选择器重做
  • 成绩对比与历史曲线
  • 空态 / 首次引导
  • 键盘可达性与 aria 补全
07

验收标准

升级是否完成，用这 10 条判断，而不是"看起来好看了"。

所有正文对比度 ≥ 4.5:1，大字 ≥ 3:1
390px 宽度下无横向滚动
四个模式的首屏版式完全一致
进入页面 3 秒内能开始打字
打字过程中可见速度 / 准确率 / 进度
重开操作有文字标签且可键盘触发
品牌标志在 16px 下可辨识
40 个主题切换后版式不塌陷
键盘 Tab 可遍历全部交互元素
首屏 LCP < 1.5s（不引入新字体文件）
评审依据：本地 vite dev 真实渲染截图（1440×900 / 390×844）、源码逐文件核对、WCAG 2.1 对比度实测。
范围说明：本方案只改视觉与信息架构，不涉及打字引擎逻辑与 40 套主题的配色值。
